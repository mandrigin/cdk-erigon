# Glossary

Terms and definitions used in cdk-erigon documentation.

## A

### Agglayer

Polygon's aggregation layer for unified liquidity across chains.

## B

### Batch

A collection of L2 blocks submitted together for ZK proof generation.

## F

### Fork ID

Protocol version identifier for zkEVM. Fork IDs track network upgrades.

## G

### Global Exit Root (GER)

A hash committing to the state of all exit trees, enabling cross-chain bridge verification.

## L

### L1 Info Tree

Merkle tree containing L1 block information accessible from L2.

### Local Exit Tree

Per-chain Merkle tree of withdrawal claims.

## P

### Patricia Merkle Trie (PMT)

Standard Ethereum state trie using Keccak hashing.

### Pessimistic Proof

Proof type used by Agglayer for cross-chain security.

### Poseidon Hash

ZK-friendly hash function used in Sparse Merkle Trees.

## S

### Sequencer

Node responsible for ordering and producing L2 blocks.

### Sparse Merkle Tree (SMT)

ZK-optimized state trie using Poseidon hashing for efficient proof generation.

## T

### Trusted State

L2 state processed by sequencer but not yet submitted to L1.

## U

### Unified Bridge

Polygon's cross-chain bridge infrastructure.

## V

### Validium

L2 architecture where data is stored off-chain with data availability guarantees.

### Verified State

L2 state with ZK proof verified on L1.

### Virtual State

L2 state submitted to L1 but not yet proven.

## W

### Witness

Data required to generate a ZK proof for state transitions.

## Z

### zkCounters

Resource metrics for ZK proof generation (steps, memory, hashes, etc.).

### zkEVM

Zero-knowledge Ethereum Virtual Machine - EVM-compatible execution with ZK proofs.

### zkRollup

L2 scaling solution using ZK proofs for state validity.
